# Сборки предметов

Модуль `app/Modules/ItemAssembly` отделён от крафта по рецептам. Сборка не требует книги, изучения рецепта или особого «осколка-рецепта».

## Данные

- `item_assemblies`: локализованное название, строковый `type` (`artifact`, `equipment`, `consumable`, `misc`), `result_mode` (`random` или `fixed`), активность, сортировка.
- `item_assembly_components`: сборка, предмет справочника, количество.
- `item_assembly_rewards`: сборка, предмет справочника, количество и положительный вес.

В случайном режиме выдаётся ровно одна запись награды, вероятность равна её весу, делённому на сумму весов. Количество берётся из выбранной записи. В фиксированном режиме разрешена одна запись награды; вес игнорируется. Сама сборка гарантированна.

## Выполнение

`AssembleItem` работает внутри транзакции: блокирует игрока и сборку, проверяет активность и конфигурацию, блокирует подходящие ячейки рюкзака, суммирует количество по всем стопкам, проверяет весь набор и только затем списывает компоненты и выдаёт награду через `BackpackService`. Надетые и просроченные предметы не учитываются. Ошибка выдачи откатывает списание.

`AssemblyCatalog` отдаёт список по типу, наличие компонентов и предметы для стандартных тултипов. Кузня показывает только `artifact` и отправляет POST `/blacksmith/{id}/assemblies/{assembly}` с CSRF. Для кузни дополнительно проверяются тип структуры и текущая локация игрока. Другие игровые точки смогут использовать тот же сервис с собственной проверкой доступа.

Ответ содержит фактический `crafted_share_item_id` и `quantity`. Анимация подсветки не выбирает награду, а останавливается на ID из ответа сервера.

## Администрирование

Раздел `/admin/item-assemblies`: фильтр по типу и названию, создание и редактирование. Компоненты и награды выбираются через AJAX Select2 с пагинацией. Веса редактируются здесь, а не в рецепте предмета. Сборку можно отключить; удаление не требуется.

## Перенос старых сборок

Применяются только две миграции:

1. `2026_10_19_000002_create_item_assemblies.php`.
2. `2026_10_19_000003_move_artifact_assemblies_out_of_recipes.php`.

Переносятся только одноразовые случайные рецепты с якорем типа resource/misc, гарантированным успехом и пулом из артефактов. Также поддерживается первоначальный «Осколок …» типа recipe: он становится resource, а его расход добавляется в компоненты, если раньше он расходовался как книга. Настоящие книги рецептов и прочий крафт не изменяются. Сохраняются все ID предметов, количества компонентов и веса наград. Инвентари, магазины и дроп не переписываются.

После проверки перенесённой конфигурации старая запись рецепта и её связи удаляются. Точный снимок этих строк хранится в `legacy_recipe_snapshot` для отката миграции. Если при откате старый ID уже занят, операция останавливается без перезаписи чужих данных.

До применения миграций каталог новых сборок пуст. Старый endpoint `combine-shards/{recipe}` удалён; операции по-прежнему нельзя выполнять через рецепт-якорь. Сборки создаются исключительно в новых таблицах.
