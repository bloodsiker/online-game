# Telegram и API персонажа

Модуль `app/Modules/Telegram` добавляет привязку в `/settings`, обработку команд бота и серверное API только для чтения. Обработчики бота и API используют одни и те же сервисы чтения персонажа и торговых площадок.

## Подключение

1. Создать бота через BotFather. В окружении приложения указать:

   ```dotenv
   TELEGRAM_BOT_USERNAME=your_game_bot
   TELEGRAM_BOT_TOKEN=token_from_botfather
   TELEGRAM_WEBHOOK_SECRET=independent_random_secret_at_least_32_characters
   TELEGRAM_API_SECRET=another_independent_random_secret_at_least_32_characters
   ```

   Username — без `@`. Секреты должны различаться; для webhook допустимы только латинские буквы, цифры, `_` и `-`, длина 32–256. Можно получить каждый секрет отдельным вызовом `openssl rand -hex 32`. Не помещать секреты в браузер, мобильный клиент, URL или репозиторий. `TELEGRAM_API_SECRET` нужен только для отдельного доверенного серверного клиента API; встроенный обработчик бота вызывает общие сервисы напрямую.

2. Применить только новую миграцию:

   ```sh
   php artisan migrate --path=database/migrations/2026_11_06_120000_create_telegram_links_tables.php --force
   php artisan config:clear
   ```

3. На сервере с публичным HTTPS-адресом зарегистрировать webhook:

   ```sh
   php artisan telegram:set-webhook --url=https://game.example.com
   ```

   Можно опустить `--url`, если `APP_URL` уже содержит публичный HTTPS URL. Для Docker команды выполняются через `docker compose exec -T php-www ...` из корня проекта. `localhost` недоступен серверам Telegram: для локальной проверки нужен публичный HTTPS-туннель. Команда не удаляет ожидающие обновления Telegram. Одна учётная запись бота использует один webhook: не регистрировать локальный адрес для рабочего бота.

4. Войти в игру с подтверждённой почтой → Настройки → Telegram → Привязать Telegram. Открыть полученную ссылку в Telegram, нажать «Начать» и обновить настройки игры.

До заполнения параметров подключения настройки показывают, что Telegram недоступен. Никакие реальные токены автоматически не создаются и не отправляются.

## Привязка и доступ

- Одноразовая ссылка действует 10 минут; новая ссылка отменяет предыдущую. В таблице `telegram_link_tokens` хранится SHA-256 хеш, не сам токен.
- Один Telegram соответствует одному игровому аккаунту и наоборот. Уникальные индексы и транзакции защищают от одновременной привязки. При смене Telegram сначала нужна отвязка в игре.
- `/start <token>` принимается только в личном чате, где Telegram ID отправителя совпадает с ID чата. Группы, каналы, сообщения ботов и другие типы обновлений игнорируются.
- Webhook проверяет `X-Telegram-Bot-Api-Secret-Token`. Он не использует игровую сессию. CSRF отключать для браузерных действий не требуется: привязка и отвязка в настройках остаются под `web`, `auth`, проверкой почты и CSRF.
- После отвязки новые запросы к данным сразу запрещены. Уже полученные пользователем сообщения в Telegram не удаляются.
- Webhook возвращает ответ `sendMessage` непосредственно Telegram. Нет фоновой очереди и дополнительного сетевого запроса на каждую команду. Telegram не возвращает результат доставки при таком способе ответа.
- Повторная доставка одного `update_id` возвращает сохранённый ответ, не повторяя привязку. Ответы хранятся 7 дней, просроченные ссылки и старые ответы ежедневно удаляет `telegram:prune` через стандартный Laravel scheduler. Отдельный cron для него не нужен, если `schedule:run` уже работает.
- Язык ответов и названий предметов — из настроек игрока. До привязки используется `language_code` Telegram (uk или ru).

Документация Telegram: [ссылки для привязки](https://core.telegram.org/bots/features#deep-linking), [защита webhook](https://core.telegram.org/bots/api#setwebhook), [ответ методом Bot API на webhook](https://core.telegram.org/bots/api#making-requests-when-getting-updates).

## Команды бота

| Команда | Действие |
|---|---|
| `/start` или `/help` | Меню и подсказка |
| `/character` | Никнейм, уровень, монеты и бриллианты |
| `/auction` | Собственные активные лоты аукциона на всех торговых площадках |
| `/exchange` | Собственные активные заявки на покупку на бирже |
| `/auction 2`, `/exchange 2` | Следующая страница, по 10 записей |

После привязки доступны и кнопки меню. Покупка, продажа, отмена лотов, вывод денег и игровые действия через бота не добавлены.

## API v1

Все запросы идут по HTTPS **между доверенными серверами**. Заголовки обязательны:

```http
X-Telegram-Api-Secret: <TELEGRAM_API_SECRET>
X-Telegram-User-Id: <Telegram ID отправителя команды>
Accept: application/json
```

`X-Telegram-User-Id` доверенный сервер берёт из проверенного обновления Telegram, а не из пользовательского ввода. Общий секрет даёт серверный доступ к привязанным аккаунтам: его нельзя выдавать игрокам. Параметр игрового `user_id` не принимается: персонаж определяется по действующей привязке. Игровые cookie и логин бота не требуются.

| Метод и путь | Результат |
|---|---|
| `GET /api/v1/telegram/character` | Персонаж и баланс |
| `GET /api/v1/telegram/auction-lots?page=1&per_page=10` | Лоты игрока |
| `GET /api/v1/telegram/exchange-orders?page=1&per_page=10` | Заявки игрока |

Лимит: 60 запросов в минуту на привязанный Telegram. `per_page`: 1–50. По умолчанию — 10. Изменяющих методов API нет. Ответы не кэшируются.

Пример персонажа:

```json
{
  "ok": true,
  "data": {
    "nickname": "Player",
    "level": 35,
    "money": 10000,
    "diamonds": "56.75"
  }
}
```

Бриллианты — строка с двумя знаками после точки, чтобы не терять дробную часть баланса. Монеты — целое число.

Пример лотов:

```json
{
  "ok": true,
  "data": [{
    "id": 12,
    "structure_id": 9,
    "item_id": 123,
    "share_item_id": 1748,
    "name": "Ветряной Хрусталь",
    "quantity": 4,
    "total_price": 100,
    "unit_price": 25,
    "created_at": "2026-11-06T12:00:00+00:00"
  }],
  "meta": {"current_page": 1, "last_page": 1, "per_page": 10, "total": 1}
}
```

У заявок биржи такая же оболочка и поля, кроме `item_id`: заявка относится к справочному `share_item_id`. У аукциона `price` в игре — сумма за весь лот, у биржи — за единицу; API явно разделяет `total_price` и `unit_price`. Старые/выполненные заявки и лоты не перечисляются: читаются только текущие строки с положительным количеством. Невыкупленная выручка и история операций не входят в этот API.

Ошибки: `401` — неверный секрет; `403` — нет привязки или персонаж недоступен; `422` — неверные параметры; `429` — превышен лимит. Webhook имеет отдельный секрет и лимит 120 сообщений в минуту на отправителя.

## Проверка без основной базы

```sh
docker compose exec -T -e DB_CONNECTION=sqlite -e DB_DATABASE=:memory: -e SESSION_DRIVER=array -e CACHE_STORE=array php-www php artisan test tests/Feature/Modules/Telegram/TelegramIntegrationTest.php tests/Unit/Frontend/GameSettingsPageTest.php
```

Тесты дополнительно принудительно включают SQLite в памяти и создают только минимальные тестовые таблицы. `RefreshDatabase`, пересоздание основной базы и полный запуск миграций в них не используются.
