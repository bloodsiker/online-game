# Баланс статов премиум-артефактов

Методика и текущие цифры для 9 премиум-артефактов премиум-магазина
(structure_id=10, категория «Артефакты»): 927-930, 1830-1832 (эндгейм,
героик/легендарка, уровень 35-50), 1833-1834 (стартовые, легендарка,
уровень 1). См. также `docs/premium-artifact-pendant-prompts.md` (лор,
промпты картинок).

## Методика

Игрок получает **~10 «сырых» очков статов за уровень**: 5 `free_stats` на
ручное распределение + ~5 автоприроста расы за левел-ап (сумма у Человека:
`0.8×5 + 1(выносливость) = 5`, см. `RecalculatePlayerStats`, `races.free_stats`).

Не все типы `share_item_stats.stat_type` одинаково «конвертируемы» в эти
очки — часть напрямую повторяет формулы игрока (1:1 или с известным
коэффициентом), часть — чистый бонус без аналога у игрока:

**Конвертируемые 1:1** (формулы из `PlayerStatFormulas`):
- `dodge` ← agility (`DODGE_PER_AGILITY = 1`)
- `critical` ← intuition (`CRITICAL_PER_INT = 1`)
- `armor` ← strength (`ARMOR_PER_STR = 1`)
- `magic_resistance` ← wisdom (`MAGIC_RESIST_PER_WIS = 1`)
- `magic_attack` ← **intelligence** (см. ниже — важная поправка)
- raw `agility`/`intuition`/`wisdom`/`intelligence`/`endurance` как
  предметный стат — это буквально то же самое первичное значение, что и
  вложенное игроком (входит в тот же `primaryBase` до применения формул,
  см. `PlayerStatService::buildSheet()`)

**Конвертируемо с коэффициентом:**
- `hp_max` ÷ 3 ← endurance (`HP_PER_ENDURANCE = 3`)

**Важная поправка (была ошибка в первом проходе расчёта):** `magic_attack`
изначально посчитали «эксклюзивным» статом без аналога у игрока. Это
неверно — `MagicHitCalculator::magicPower()`:
```php
private function magicPower(FightHitInterface $caster): float
{
    return (float) ($caster->getIntelligence() + $caster->getMagicAttack());
}
```
`intelligence` (сырой стат игрока) и `magic_attack` (предметный стат)
складываются 1:1 в одну формулу силы заклинаний/лечения — то есть
`magic_attack` с предмета **полностью эквивалентен** вложенному очку
intelligence. Исправлено во всех расчётах ниже.

**Истинно эксклюзивные** (нет вообще никакой формулы у игрока — сверка
по `MagicHitCalculator`/`PlayerStatFormulas`):
- `magic_critical` — база 0, целиком с экипировки
- `magic_crit_damage` — фиксированная база 175%, предмет добавляет поверх
- `crit_damage` (физический) — есть база 175% + нелинейный (софткап)
  бонус от intuition через `critDamageBonus()`, не прямая замена очкам
- `block_chance`/`block_flat`/`block_percent` — целиком с экипировки
  (щиты), на этих артефактах не используются

**⚠️ `attack_min`/`attack_max` НЕ РАБОТАЮТ на предметах type=artifact —
НИКОГДА НЕ СТАВИТЬ их на артефакты.** Работают только на обычном оружии
(`fromEquipment()` обрабатывает их по слотам рук). Артефакты идут через
`fromArtifacts()` → `PlayerStatService::mapStatType()`, а там для
`ShareItemStatType::ATTACK_MIN`/`ATTACK_MAX` нет `match`-веток — стат
тихо падает в `default => null` и отбрасывается (`fromArtifacts()`,
`if ($mappedStat === null) { continue; }`). Было реально найдено на
«Печати Пробуждения» (1833: attack_min 8/attack_max 12 висели мёртвым
грузом) и исправлено — заменено на критический удар/магическую атаку
(которые в `mapStatType()` поддержаны). Если захочется снова дать
артефакту «урон оружием» — нужно либо расширить `mapStatType()` под
хэндлинг атаки без привязки к руке, либо не пытаться вовсе.

## Целевой бюджет

- **Эндгейм-арты (927-930, 1830-1832):** конвертируемая часть = **25%**
  от естественного запаса на требуемом уровне (`10 × (уровень − 1)`).
  Премиум-арты должны давать больше, чем обычные боссовые дропы (которые
  тоже появятся и будут давать меньше) — отсюда именно 25%, а не меньше.
- **Стартовые арты (1833-1834, уровень 1):** естественный запас на 1
  уровне = 0, поэтому процент не считается — вместо этого смотрим
  «эквивалент уровня» (конвертируемо ÷ 10). Специально сделаны сильными
  относительно уровня 1 — это осознанный буст для старта игры, а не
  эндгейм-баланс.

уровням, это главная точка сравнения.

## Как пересчитывать при правке

Баланс статов существующих предметов меняется **прямым SQL `UPDATE`**,
без миграций (см. memory `feedback_item_balance_direct_sql`). Новые
предметы с нуля — по-прежнему через миграцию (паттерн
`database/migrations/2026_09_07_000003_seed_revival_sphere_item.php`).
