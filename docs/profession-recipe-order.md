# Рецепты профессии: админка и порядок в игре

На `/admin/skill/{skill}` есть ссылка «Рецепты профессии». `/admin/skill/{skill}/recipes` показывает только рецепты, чей предмет связан с этим навыком через `share_items.skill_id`. Указаны ссылка на редактирование предмета-рецепта, результат, требуемый навык и тип использования.

Строки перемещаются за ↕ или клавишами ↑/↓ на маркере. «Сохранить порядок» отправляет полный список ID рецептов на защищённый CSRF POST `admin.skill.recipes.order`. UseCase блокирует навык и соответствующие рецепты, проверяет точное совпадение состава. Чужие/неполные/повторяющиеся/устаревшие списки не сохраняются; ингредиенты, количества и вероятность результата не меняются.

Порядок хранится в `share_recipes.sort_order`. Явно упорядоченные записи идут первыми, затем записи с 0, с дополнительной сортировкой по ID. Поэтому исходная последовательность сохраняется до настройки, а новые записи без заданного порядка появляются в конце. `GetWorkshopPage` и `EloquentBlacksmithReadRepository::getCraftRecipes` используют этот порядок.

Миграция `2026_11_05_000001_add_sort_order_to_recipes.php` применена отдельно после полного бэкапа `storage/app/backups/manual/game_before_profession_recipe_order_1793870675983.sql.gz` (2,1 МБ, права 0600, gzip проверен). До/после: 9 пользователей, 156 рецептов. SHA-256 JSON всех прежних полей рецептов в порядке ID совпал: `761f7e02f152dca0cabe7ee1e60984960b441a2b41a9e6c1b4a5dbc2036454dc`. Новое поле имеет 0 для всех существующих записей; другие миграции не запускались.

Проверки выполнялись только на SQLite `:memory:`: 36 тестов / 229 assertions для профессий, рецептов, копирования предметов и ингредиентов; затем два дополнительных сценария подтвердили порядок непосредственно в GetWorkshopPage и списке одноразовых рецептов кузни (вместе с пятью тестами новой админки: 7 passed / 22 assertions). Выполнены Pint, diff-check, Node-проверки синтаксиса и работы перемещения/сериализации списка. MySQL-конкурентные тесты не запускались.
