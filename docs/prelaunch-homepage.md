# Главная страница до открытия игры

В `.env` приложения:

```dotenv
GAME_PRELAUNCH=true
```

Вход, регистрация в шапке и создание аккаунта в блоке входа открывают модальное окно с информацией о разработке. Ссылка в нём раскрывает форму email. Enter в форме входа тоже открывает окно. Логин/пароль из этой формы не отправляются. Прямые маршруты входа и регистрации для разработки остаются доступными: это переключатель публичной главной страницы, а не запрет доступа ко всей игре.

Подписчики хранятся отдельно в `game_launch_subscribers`: уникальный нормализованный email, язык RU/UK, дата подписки и дата отправленного уведомления. Аккаунт игрока не создаётся, письмо при подписке не отправляется. POST защищён CSRF, валидацией email и ограничением частоты запросов.

Список доступен администраторам в меню **«Подписки на открытие»** (`/admin/launch-subscriptions`). Есть поиск по email, фильтры языка/статуса и пагинация по 50 записей. Список работает и после отключения `GAME_PRELAUNCH`.

Применить только новую миграцию:

```bash
docker compose exec -T php-www php artisan migrate --path=database/migrations/2026_11_06_000001_create_game_launch_subscribers_table.php --force
```

Если конфигурация закэширована, после изменения `.env` выполните `php artisan config:clear` (или пересоберите config cache при развёртывании).

## Открытие игры и уведомление

1. Установить `GAME_PRELAUNCH=false` и применить конфигурацию: главная снова использует обычный вход и регистрацию.
2. Проверить SMTP-настройки и публичный `APP_URL`.
3. Посмотреть число ожидающих подписчиков без отправки:

```bash
docker compose exec -T php-www php artisan game:announce-launch
```

4. Отправить письма:

```bash
docker compose exec -T php-www php artisan game:announce-launch --send
```

Команда блокирует параллельный запуск через cache lock и не отправляет письма при включённом режиме разработки. Письмо использует игровой дизайн и язык подписчика. Успешные отправки отмечаются `notified_at` и пропускаются при повторном запуске. При ошибке отправка доступна для повторной попытки. Как и для обычной SMTP-доставки, сбой процесса между принятием письма SMTP-сервером и записью даты в БД может привести к повторному письму.

Автоматического триггера на изменение `.env` нет: переключатель не запускает рассылку.
