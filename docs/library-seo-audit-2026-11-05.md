# Технический SEO-аудит библиотеки — 2026-11-05

Проверены общие шаблоны библиотеки/статей, маршруты, robots.txt и метрики всех 45 опубликованных статей в активных категориях. Семантический анализ каждого текста/поисковых запросов и проверка индексации публичного домена не выполнялись. Ниже сохранены результаты исходного аудита; исправления перечислены отдельно.

## Выполнено после аудита

- Публичные страницы библиотеки: `/ru/library`, `/uk/library`. С 06.11.2026 статьи используют `/{locale}/library/{category}/{slug}` с собственной категорией статьи в пути. Язык URL приоритетнее языка сессии/настроек и не меняет настройки игрока. Старые локализованные адреса `/{locale}/library/{slug}` перенаправляются с кодом 301; лишний query-параметр `category` удаляется. Старые именованные маршруты и адреса `/library...` без языка сохранены как временные перенаправления с учётом языка игрока. Остальные query-параметры сохраняются. На страницах есть ссылки переключения RU/UK.
- Для всех статей общий SEO-шаблон: локализованные title, H1, lang/Content-Language, description из excerpt (при отсутствии — очищенный контент без HTML/шорткодов), canonical без параметров категории/отслеживания, взаимные hreflang и x-default, Open Graph и Twitter Card. Изображение: обложка статьи → изображение категории → стандартная картинка библиотеки.
- Ссылки навигации/форм библиотеки и локальные библиотечные ссылки в HTML статей сохраняют выбранный язык. Непереведённая статья перенаправляет на существующий язык, отсутствующий перевод не объявляется в hreflang и sitemap.
- Canonical, Open Graph URL, hreflang, dropdown статей и sitemap используют адрес с категорией без `?category`. Если категорию статьи перенесли/переименовали, старый путь перенаправляется на актуальный. Генерация ссылок для списков/sitemap использует загруженные категории без отдельного SQL-запроса на каждый URL.
- `/sitemap.xml` формируется автоматически из доступных опубликованных статей и реальных страниц библиотеки. Черновики, будущие публикации, удалённые статьи и неактивные категории исключены. Обычные категории пока перенаправляют на первую статью, поэтому такие промежуточные URL в sitemap не включены. При первоначальной HTTP-проверке: 96 URL библиотеки, по 48 на RU/UK (45 статей + главная библиотеки + бестиарий + карты). С 06.11.2026 общий генератор также добавляет форум: главную, активные разделы, темы и их пагинацию; подробности в `docs/sitemap.md`.
- `robots.txt` теперь формируется Laravel и содержит абсолютный Sitemap URL текущего сайта. Локальному Nginx добавлены точные исключения для этих двух динамических файлов. Production-шаблон Nginx уже направляет отсутствующие XML/TXT файлы в Laravel.
- Поиск и фильтры — `noindex, follow`, обычная пагинация бестиария имеет собственный canonical; посторонние tracking-параметры исключены. Просмотры статьи больше не изменяют updated_at, чтобы не подменять дату изменения контента в sitemap/OG.
- Базовый layout используется также форумом: он продолжает работать без SEO-данных библиотеки. Миграции и правки контента статей не нужны.

Остались отдельными задачами: JSON-LD Article/BreadcrumbList, самостоятельные посадочные страницы обычных категорий, мобильные/скоростные измерения, редакторская оптимизация и Search Console на публичном домене.

## Подтверждено

- `/library` отвечает HTTP 200 гостю и отдаёт серверный HTML, без iframe. Статьи тоже формируются сервером (`LibraryController::show`, `LibraryShortcodeRenderer`), но HTTP-обход всех статей не выполнялся: он увеличивал бы views_count. Метрики получены read-only через модели.
- Все 45 публичных статей имеют непустой контент и excerpt на RU/UK; дубликатов заголовков внутри каждого языка нет. В исходном HTML контента всех 45 статей отсутствует H1. Общий layout/show тоже не создают H1.
- Есть отдельные slug-маршруты, уникальные title, обычные ссылки на категории и статьи, alt у обложек/плиток, 404 для недоступных статей. Публикация и активность категории проверяются сервером.
- `layout.blade.php` содержит только charset, viewport и title из SEO-метаданных. Нет meta description, canonical, Open Graph, hreflang и JSON-LD. Title формируется как «Название — Библиотека», без бренда «Вечность». Excerpt в description не используется.
- `lang="ru"` прописан статически; язык контента зависит от сессии/настройки пользователя через ApplyGameLocale. Для RU/UK нет отдельных стабильных URL в маршрутах библиотеки.
- Одну статью можно получить с category-параметром и без него, в том числе с разным контекстом родительской категории; canonical не задан. Параметры поиска/фильтров/пагинации не имеют отдельной политики индексации.
- `/sitemap.xml` отвечает 404. В `robots.txt`: `User-agent: *`, пустой Disallow; ссылка на sitemap не задана. Отсутствие sitemap не запрещает индексацию, но отсутствует явный список URL для обнаружения страниц.
- Обычная категория без поискового запроса редиректит на первую статью, поэтому самостоятельная посадочная страница категории не формируется.
- Крошки видимы, но BreadcrumbList не сформирован. Связанные игровые объекты в show отображаются span-бейджами; ссылки на сущности зависят от конкретных shortcode-карточек в тексте.
- Layout использует фиксированные колонки 290/730 px и ряд CSS/JS-файлов. Мобильная компоновка и Core Web Vitals не измерялись; одного viewport недостаточно для подтверждения адаптивности. Наличие OG/JSON-LD само по себе не гарантирует позиции/расширенные результаты.

## Приоритеты

1. Общие SEO-метаданные для библиотеки и всех статей: уникальные title/description с fallback из title/excerpt, один смысловой H1, правильный lang, canonical без навигационных дублей.
2. Стабильные языковые URL для публичной библиотеки и корректные hreflang/canonical на том же языке; серверное переключение по сессии не обеспечивает обнаружение обеих версий.
3. Sitemap только публичных URL (включая языковые версии), политика для поиска/фильтров, отдельные полезные категории вместо редиректа на произвольную первую статью.
4. Article/BreadcrumbList, OG для превью, мобильная проверка, оптимизация подключаемых ресурсов по измерениям.
5. Отдельная редакторская проверка текстов, поисковых намерений и перелинковки; после публикации — Search Console на реальном домене. Локальный localhost не позволяет проверить внешнюю индексацию.
