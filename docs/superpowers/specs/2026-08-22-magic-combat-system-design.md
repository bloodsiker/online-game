# Полноценная боевая магическая система

Дата: 2026-08-22

## Цель

Довести боевую магию до полноценной подсистемы, симметричной оружейной: собственный урон-калькулятор, собственная защита (магическое сопротивление), изучение заклинаний через книги с требованиями, и полный набор типов навыков — атака, DoT, лечение, баф, дебаф.

Это надстройка над уже реализованным в текущей сессии: 3 атакующих заклинания («Огненная искра» 1 lvl, «Огненный залп» 20 lvl, «Испепеляющий вихрь» 55 lvl, зеркалящие тиры оружия), навык «Колдовство», таблица `magic_skill_requirements`.

## Что уже есть и что в этом неправильно

- `MagicAttackStrategy` зовёт тот же `HitCalculator::hit()`, что и оружие → физический Уворот цели «спасает» от заклинания, физический Крит атакующего его крит-анует, броня цели режет магический урон так же, как физический. Магии нет как отдельной механики.
- `PlayerStatService::buildSheet()` сейчас (после вчерашнего патча) считает `magic_attack = intelligence` — это неверно: `magic_attack` должен быть **чисто от экипировки** (как `block_chance`/`block_flat`), а интеллект — отдельный, независимый источник силы магии. Патч отменяется этой спекой.
- Требования на заклинание (`magic_skill_requirements`) сейчас проверяются в `UpdateEquippedMagicSkills` (при экипировке) — баг: временный съём предмета с интеллектом выкидывает уже честно выученное заклинание из активных слотов. Требования должны проверяться один раз — при изучении.
- Заклинания выдаются только сидером напрямую игроку — нет игрового пути их получить.
- Ни у боевой атаки, ни у магии нет защиты от гонки при двойном клике (ни `throttle`, ни `lockForUpdate`) — общая дыра боевой системы. В этой спеке чиним только новые магические эндпоинты, физику не трогаем.

## Правила (зафиксировано, не обсуждается заново)

1. **Магия не уворачивается, не критует, не блокируется щитом.** Собственный путь расчёта — `MagicHitCalculator`, не `HitCalculator::hit()`. Единственная защита цели — магическое сопротивление.
   > **Обновлено 2026-08-30**: часть про крит больше не абсолютна — с введением магического оружия (посох/жезл/сфера) магия может критовать, но только через отдельный не контестуемый механизм (`getMagicCriticalChance()`, база 0 — только с экипировки). Уворот и блок щитом по-прежнему не действуют. См. `docs/superpowers/specs/2026-08-30-magic-weapons-design.md`.
2. **DoT считает силу тика один раз, при наложении эффекта**, через `MagicHitCalculator` (полная формула: базовый ролл + интеллект/power_coefficient − сопротивление цели на тот момент). Каждый следующий тик применяет уже посчитанное фиксированное значение — не бросает урон заново и не пересчитывает сопротивление цели.
3. **Требования (`magic_skill_requirements`) проверяются только при изучении книги.** Экипировка уже изученного заклинания требований не проверяет.
4. **Мудрость получает вторую роль** (MP + магическое сопротивление) — не меняем модель, но добавляем это явным пунктом в тестовый чек-лист (симуляции на 20/55/100 lvl), т.к. у остальных первичных стат тоже по 2 роли (Сила → броня + % урона, Интуиция → крит + доля класса), это последовательно.

## Данные и миграции

- `ShareItemStatType::MAGIC_RESISTANCE` (новый кейс) — растёт как `armor`, но от **Мудрости**: `magic_resistance = max(0, (wisdom-1) × MAGIC_RESIST_PER_WIS) + бонусы с экипировки`. Константа `MAGIC_RESIST_PER_WIS` по аналогии с `ARMOR_PER_STR = 1`.
- Правка `PlayerStatService::buildSheet()`: `magic_attack` возвращается к базе **0**, растёт только модификаторами от `ShareItemStatType::MAGIC_ATTACK` (откат вчерашнего патча `= primary['intelligence']`).
- `StatSheet` + `FightHitInterface`: добавить `getMagicResistance(): int` (мирроринг уже добавленного `getIntelligence()`). Реализовать в `StatSheet`, `Monster` (0, как и с интеллектом), `SimulateBattleTriangle` (0).
- `magic_skills.power_coefficient` (float, per-skill) — заменяет вчерашний универсальный `PlayerStatFormulas::intelligenceDamagePercent()` для боевых заклинаний. Формулу из `PlayerStatFormulas` не удаляем физически (используется силой для оружия), но для магии больше не вызываем.
- `ShareItemType::BOOK` (новый кейс).
- `magic_skill_books`: `id, share_item_id (FK, unique), magic_skill_id (FK, unique), created_at, updated_at` — связь 1:1, книга ↔ заклинание.
- Таблицы `player_active_effects`, `monster_active_effects`, `effects` уже существуют и уже поддерживают refresh-длительности вместо стака (проверено в `BattleEffectService::applyEffectToPlayer/applyEffectToMonster`) — новых миграций под DoT/баф/дебаф не требуется, только новые строки данных.

## Формула урона и защиты

```
сила_магии = intelligence + magic_attack (с экипировки, MAGIC_ATTACK-стат)
rawDamage  = random(min_damage, max_damage) + round(сила_магии × power_coefficient)

damageMultiplier  = A / (A + magic_resistance)   // A — своя константа, тот же levelScale, что у брони (REFERENCE_LEVEL=12)
resistancePercent = magic_resistance / (A + magic_resistance)   // для отображения в UI/логах
finalDamage = max(1, round(rawDamage × damageMultiplier))
```

`MagicHitCalculator` — новый класс рядом с `HitCalculator` (`Combat/` namespace), принимает `FightHitInterface $attacker, FightHitInterface $defender, MagicSkill $skill` (или явные `min/max/power_coefficient` для DoT-тика без объекта скилла). Не содержит уворота/крита/блока щитом.

Константа `A` в знаменателе (`MAGIC_RESIST_CONSTANT`) — стартовое значение = `220` (то же, что `HitCalculator::ARMOR_CONSTANT`, для паритета кривых брони и резиста на старте), финальное значение калибруется через `battle:simulate-pve` так же, как `power_coefficient` — не вбивается вручную «на глаз».

Стартовые `power_coefficient` (ориентиры из плана, финальная настройка — по симуляциям):

| Тип | power_coefficient |
|---|---|
| Базовый удар | 0.25–0.35 |
| Тик DoT | 0.10–0.14 |
| Лечение | 0.30–0.40 |

Существующие 3 атакующих заклинания получают `power_coefficient` в этом диапазоне вместо текущего мультипликатора ×1.3 к урону оружия — конкретные числа считаются на этапе реализации через `battle:simulate-pve`, не вбиваются вручную.

## Общий механизм каста (мана + кулдаун)

Один сервис/метод для обоих путей применения (в бою — атака/DoT через `AttackService`, вне боя — баф/хил/дебаф через `UseMagicSkill`):

1. Проверка «заклинание изучено» (существует `player_magic_skills` строка).
2. Проверка `cooldown_end_at` (для атакующих — 0, реального ограничения нет, кулдаун только у бафов/хилов/дебафов).
3. Проверка `mp_now >= mana_cost`.
4. Атомарно: списать ману + выставить новый `cooldown_end_at` — под блокировкой (`lockForUpdate` на строку игрока или короткий `Cache::lock` по ключу `player_id:magic_skill_id`), чтобы два параллельных запроса не списали ману дважды и не проскочили кулдаун одновременно.
5. При провале любой проверки — не списывать ману, не трогать кулдаун.

Это выносится из `UseMagicSkill` в отдельный сервис (например `MagicCastGuard`), чтобы боевой путь (`MagicAttackStrategy`) тоже мог им пользоваться — сейчас он списывает ману без всякой блокировки.

## Изучение по книгам

1. Книга — обычный `share_item` типа `BOOK`, продаётся в магазине как любой другой предмет.
2. В рюкзаке для книги — отдельная кнопка «Изучить» (контекстное меню, по образцу уже существующего «Использовать», но отдельный пункт и отдельный route, не через `ItemEffectStrategyFactory` — изучение не мгновенный эффект, а сложная транзакция с проверками).
3. Новый use case `LearnMagicSkillFromBook`:
   - находит книгу в рюкзаке игрока (владение, count ≥ 1);
   - резолвит связанное заклинание через `magic_skill_books`;
   - проверяет, что заклинание ещё не изучено;
   - проверяет требования через уже существующий `MagicSkillRequirementService` (единственное место, где эта проверка происходит);
   - в транзакции: списывает ровно одну книгу, создаёт `player_magic_skills`.
4. Любая ошибка — книга не расходуется.
5. `UpdateEquippedMagicSkills` теряет вызов `MagicSkillRequirementService` (откат вчерашнего добавления) — экипировка становится простым тогглом среди уже изученных заклинаний, как было исходно.

## DoT / баф / дебаф / лечение

Полностью на существующей модели `Effect` + `BattleEffectService` (уже умеет refresh длительности вместо стака):

- **DoT**: тик раз в 2 сек, длительность 6–8 сек, кулдаун каста 6–10 сек. Сила тика фиксируется один раз при `applyEffectToPlayer/Monster` — см. правило 2.
- **Баф**: длительность 10–20 сек, кулдаун 15–30 сек, `stat_modifiers` с положительным значением.
- **Дебаф**: длительность 6–10 сек, кулдаун 8–15 сек, `stat_modifiers` с отрицательным значением. Итоговая стата не должна уходить ниже 0 — клэмп на этапе применения модификатора (`PlayerStatService::applyModifiers`), проверить/добавить, если сейчас не клэмпит.
- **Для боссов**: не полный иммунитет к дебафу, а срез длительности — единый коэффициент (например ×0.5) на все боссы и все дебафы, не per-boss/per-эффект настройка (YAGNI, тюнить позже, если понадобится точнее).
- После окончания бафа/дебафа — гарантированный пересчёт `PlayerStatService::invalidate()`.

## Стартовый набор — 7 книг

1. Огненная искра (атака, 1 lvl) — уже есть, оборачивается в книгу.
2. Огненный залп (атака, 20 lvl) — уже есть, оборачивается в книгу.
3. Испепеляющий вихрь (атака, 55 lvl) — уже есть, оборачивается в книгу.
4. DoT-заклинание (новое).
5. Самолечение (новое).
6. Баф силы магии или защиты (новое).
7. Дебаф брони либо уворота (новое).

Один архетип магии без стихийных сопротивлений и массовых заклинаний на первом релизе — то же решение, что в плане codex (позволяет быстрее проверить экономику маны и темп боёв).

## Админка и интерфейс

- Настройка книги: связанное заклинание, требования, `power_coefficient`, урон/лечение, мана, кулдаун.
- Магазин: показывает книгу с описанием заклинания, требованиями, стоимостью маны/кулдауном.
- Рюкзак: кнопка «Изучить» + список недостающих требований, если изучить нельзя.
- Экран магии: изученные заклинания, активные слоты, кулдауны, уровень «Колдовства».

## Тестирование

Расширить существующие `battle:simulate` и `battle:simulate-pve` (реальные, зарегистрированные Artisan-команды — `php artisan list battle` подтверждает) под маго-типы билдов и магический урон/резист, не создавать с нуля.

Чек-лист (по образцу плана codex, адаптированный под принятые решения):

- Книга не тратится при непройденных требованиях.
- Повторное изучение уже изученного заклинания невозможно.
- Двойной запрос на изучение не тратит две книги и не создаёт два `player_magic_skills`.
- Двойной запрос на каст не списывает ману дважды и не обходит кулдаун (тест на `MagicCastGuard`).
- Недостаток маны / активный кулдаун не запускают применение и не списывают ресурсы.
- Экипировка уже изученного заклинания не проверяет требования повторно (регрессия на правило 3).
- DoT обновляет длительность при повторном касте, а не стакается; сила тика не меняется в течение действия эффекта.
- Бафы/дебафы корректно применяются и полностью снимаются по истечении (стат пересчитан).
- Опыт «Колдовства» начисляется только при валидном применении (уже так — через `AttackService::gainExperienceSkill`, `$hit->getSkill()`).
- Магия не уворачивается/не критует/не блокируется щитом — тест на `MagicHitCalculator` напрямую, без прогона через `HitCalculator`.
- Сравнение DTPS мага и воина на контрольных уровнях (20, 55, 100) не даёт безусловного преимущества ни одной из сторон — через `battle:simulate-pve`.
- Мудрость (MP + magic_resistance одновременно) не даёт вырожденного билда на 20/55/100 lvl — тот же прогон.

## Область, оставленная вне этой спеки

- Физическая атака и её защита от даблклика — отдельная задача, не трогаем.
- Элементные сопротивления, массовые заклинания, сложные комбо — сознательно за скоуп первого релиза.
- Per-boss настройка дебаф-длительности — если общий коэффициент окажется недостаточным, отдельная спека.
