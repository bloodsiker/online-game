# Q: что ты можешь протестировать на моем окружении докера?

## Answer

Expanded from original query via vocab: [request, controller, battle, fight, attack, player, user, users, session, database, query, cache]. В текущем Docker-контуре можно измерить HTTP-нагрузку Nginx/PHP-FPM на реальных игровых сценариях, транзакции и блокировки боев в MySQL, рост battle-таблиц, браузерную производительность одного пользователя, Redis отдельно и устойчивость при ступенчатом росте конкуренции. Сейчас доступны ab, curl, MySQL Performance Schema и redis-benchmark; k6 не установлен. PHP-FPM ограничен пятью worker-процессами, MySQL имеет buffer pool 128 MiB, performance_schema включена, slow_query_log выключен, Compose не задает CPU/RAM limits. Реалистичный прогон следует делать на тестовых аккаунтах и копии БД, поскольку бои меняют состояние. Redis сейчас не представляет основной request path, если sessions/cache остаются файловыми; отдельного queue-worker сервиса в Compose нет. Для точной серверной емкости генератор нагрузки лучше вынести с того же Docker-host. Узлы FightController, FightOrchestrator, Battle и Player определяют основной боевой путь.
