# Q: как оптимизировать PHP-FPM?

## Answer

Expanded from original query via graph vocab: [php, laravel, request, fight, attack, login, battle, database, query, transaction, session, cache]. Для этого проекта оставить pm=dynamic и первым A/B-тестом увеличить pm.max_children с 5 до 8, start_servers=3, min_spare_servers=2, max_spare_servers=5, добавить pm.max_requests=500, FPM status и slowlog. Логи дважды подтвердили достижение лимита 5 workers; тест показал рост p95 с 0,639 секунды при 5 игроках до 5,296 секунды при 50. Не повышать сразу выше 8: MySQL уже доходил до 100% одного CPU, а бой выполняет DB transaction и lockForUpdate. Сначала профилировать SQL, перенести file session и cache в Redis, выполнить Laravel optimize для production. OPcache уже включён 128 MB и 10000 keys; менять только по статистике заполнения. После каждого варианта повторять один сценарий и сравнивать p95, RPS, listen queue, max children reached, CPU MySQL и lock waits.
